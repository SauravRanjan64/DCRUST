85. Your Strongest Interview Talking Points

If they ask "Why PostgreSQL?"

"The domain has strong relationships between students, jobs, companies and applications. PostgreSQL gives me foreign keys, unique constraints and transactions that are useful for placement workflows."

If they ask "Why not MongoDB?"

"MongoDB could work, but the core placement workflow is relational. I prefer PostgreSQL here because correctness and transactional consistency are more important than schema flexibility."

If they ask "Where is your business logic?"

"Business logic lives in service modules rather than React controllers. The eligibility engine is a dedicated service."

If they ask "Can frontend bypass eligibility?"

"No. The frontend only requests an eligibility check. The backend independently loads the student and job data and makes the final decision."

If they ask "How do you prevent duplicate applications?"

"I use application-level validation plus a database-level unique constraint on student and job. The database constraint protects against concurrent requests."

If they ask "Why Socket.IO?"

"Application status is useful in real time. Rather than polling continuously, the backend emits status events to the student's socket room."

If they ask "How will this scale?"

"The initial implementation is a modular monolith. Stateless API instances can be horizontally scaled behind a load balancer, Redis can handle shared cache and Socket.IO coordination, and PostgreSQL remains the source of truth."

If they ask "Is the resume matcher AI?"

"No. The current implementation is deterministic keyword matching. I intentionally kept hiring decisions explainable. A future version could add an ML/NLP service as an assistive feature, but it should not independently make recruitment decisions."
